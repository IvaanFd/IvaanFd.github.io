Cloud-Native Application Protection Platform (CNAPP) with Prisma Cloud

This project focused on the design, implementation and operationalization of a Cloud-Native Application Protection Platform (CNAPP) using Prisma Cloud by Palo Alto Networks. The objective was to provide a centralized security layer across multicloud environments, improving visibility over cloud resources, identities and workloads while establishing a consistent approach to posture management, vulnerability management and runtime protection.

The first stage consisted of onboarding and validating the different cloud environments, including Azure, AWS and Google Cloud, ensuring that the required permissions, authentication mechanisms and provider integrations were correctly configured. Particular attention was paid to maintaining a least-privilege integration model while preserving the level of visibility required by the platform.

At the posture-management layer, the project included the configuration and review of Cloud Security Posture Management (CSPM) and Cloud Infrastructure Entitlement Management (CIEM) capabilities. Cloud resources and identities were continuously assessed against security policies, misconfigurations and excessive permissions. Native and customized policies were analyzed using Prisma Cloud query capabilities to improve detection accuracy, remediation guidance and alignment with internal security requirements.

The workload-security component covered Cloud Workload Protection (CWPP) for hosts and containerized environments. Runtime telemetry, processes, network connections and suspicious execution activity were incorporated into the security analysis in order to move beyond configuration-only visibility and obtain information about the actual behavior of workloads. The project also assessed complementary controls such as WAAS for application-layer protection and Cloud Native Network Security capabilities where additional network visibility and segmentation were required.

Another key part of the work was the definition of an operational model for vulnerability and security-posture management. Dashboards, reports, alert review processes and remediation workflows were organized so that security findings could be prioritized, assigned and tracked. This included monitoring the health of cloud integrations and deployed agents, identifying coverage gaps and providing technical context to infrastructure and application teams responsible for remediation.

The result was a more unified approach to cloud security, combining configuration assessment, identity analysis, vulnerability management, workload protection and runtime visibility in a single platform. This made it possible to correlate risks across different layers of the cloud environment and move from isolated security findings towards a more contextual and risk-based operating model.

Key Areas of the Project

  • Multicloud onboarding: Integration and validation of Azure, AWS and Google Cloud environments.
  • CSPM: Continuous assessment of cloud configurations, policies and security posture.
  • CIEM: Analysis of cloud identities, permissions and excessive entitlements.
  • CWPP: Protection and runtime visibility for hosts, containers and cloud workloads.
  • Vulnerability management: Identification, prioritization and tracking of vulnerabilities affecting cloud workloads.
  • Runtime security: Analysis of processes, commands, connections and anomalous workload activity.
  • Application and network security: Assessment of WAAS and cloud-native network security capabilities.
  • Policy management: Review of native controls and creation or tuning of queries and policies for specific use cases.
  • Reporting and operations: Dashboards, security reports, coverage monitoring and remediation workflows.

Project Outcomes

The project established a centralized and scalable CNAPP operating model capable of providing security teams with a consolidated view of cloud posture, workload risks and identity exposure. It also improved the ability to detect coverage gaps, prioritize remediation and provide technical evidence to the teams responsible for each cloud environment.
